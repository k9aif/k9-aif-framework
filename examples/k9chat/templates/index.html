What does the "Streaming" badge mean?

ON — the answer appears word-by-word as the model generates it, like watching someone type in real time. The model isn't running any faster; you just stop waiting for the whole answer before seeing the first words.

OFF — K9Chat waits for the complete answer, then shows it all at once. Total time to finish is usually about the same either way.

Defaults from chat.stream in config.yaml, but clicking the badge flips a runtime override (POST /chat/stream/toggle) without touching the file -- resets to the file's default on restart. Technically: streamed requests go to /chat/stream over Server-Sent Events and call OllamaLLM.generate_stream(); non-streamed requests go to /chat and call generate() once. The "Presentation Layer" row in the trace above shows which path your last message took.

What does the "Eval" badge mean?

Not a validation loop -- it doesn't regenerate or refine the answer. K9ValidationLoopAgent's iterative-convergence pattern is a different, unrelated part of the framework. This is grading, not refining.

ON — after the model finishes its actual answer, that answer (plus your original question) gets sent to a separate LLM-as-judge call (EvaluationFactory), scored against a fixed rubric ("respond helpfully, accurately, and clearly... stay on topic, be concise, avoid irrelevant content"). The result — score, grade, verdict, rationale — is the colored pill on the assistant's bubble. One extra LLM call per turn, after the real answer, never before it.

OFF (default) — no judge call at all, zero extra cost per message.

Implemented in evaluate_response() (chat.py); toggled at runtime via POST /chat/evaluation/toggle, same override pattern as Streaming.

K9Chat is a reference SBB (Solution Building Block) built on the K9-AIF framework's ABBs (Architecture Building Blocks). This request's path through the stack:

ChatAgent

Extends BaseAgent. Formats prompt + history, calls the model router, persists the new turn.

CacheFactory → BaseCache

Backs conversation memory. In-memory by default; swap to Redis via cache.provider: redis with zero code changes.

K9ModelRouter

Weighted scoring selects the model alias, then dispatches to the LLM adapter — sync or streaming.

OllamaLLM

Concrete BaseLLM adapter. Supports generate() and token-streaming generate_stream().

Session Memory

Each browser tab keeps a session_id. History round-trips through the cache on every turn so follow-up questions keep context.

Governance

Every agent receives a governance pipeline via require_governance() — Noop in dev, enforced in production.

Projects

A Project groups a name, optional custom instructions, and a set of uploaded files — the same shape as Claude Desktop's Projects. When a project is active, its files become supplementary context for that message; the model's own knowledge and the conversation history always stay primary, and retrieved file content is clearly labeled as reference material rather than allowed to overwrite what the model already knows.

ProjectManager

CRUD for project records (name, instructions, file membership) via PersistenceFactory/SQLitePersistence — durable across restarts, unlike session chat history.

ProjectRetriever

One ChromaDB collection per project for structural isolation — a file in Project A can never leak into Project B's retrieval results.

K9Retriever + VectorDBFactory

Same retrieval ABBs the framework uses elsewhere (e.g. dow-k9-aif's DAS), just pointed at ChromaDB instead of pgvector.

K9-AIF/K9X Knowledge Base

Unlike Projects, this is always on and never selected — every message is grounded in the real K9-AIF framework and K9X ecosystem documentation, not just the conversation so far. Seeded out-of-band (seed_knowledge_base.py), not through file upload: every CLAUDE.md/SKILLS.md/README across the ecosystem, the Developer & Quick-Start guides, and every k9-aif-blogs post — docs and prose only, deliberately not raw source, since a code chunk retrieved out of context tends to mislead more than help.

KnowledgeRetriever

One fixed ChromaDB collection (k9x_knowledge_base), always queried — not per-project, not opt-in, not user-managed.

Two labeled context blocks

Knowledge-base and Project context are kept as separate labeled blocks in the prompt, never merged — misattributing a retrieved chunk's source would be worse than not labeling it at all.

Fail-open

An unseeded or unreachable knowledge base returns [] silently — the chat still works, just without extra grounding, same fallback as Projects.
